# 대화의 통장 7.0 · VIVID PASSBOOK — 실제 서비스 초기 소스코드

이 저장소는 **상용화 준비용 스타터**입니다. 운영 준비가 끝난 제품이 아닙니다. 실제로 연결되는 기능과 미구현 기능을 명확히 구분합니다.

## 포함 파일

- `index.html`, `app.js`: 통장 열기/닫기, 페이지 전환, Midnight/Bloom 테마, 회원가입, 실시간 채팅, 기록, AI 호출, 예약, 신고의 UI와 초기 클라이언트 로직
- `supabase/migrations/001_init.sql`: Auth 기반 테이블, RLS, 회원별 데이터 분리, 실시간 메시지 설정, 제한된 관리자 집계 RPC
- `supabase/functions/ai-coach/index.ts`: 로그인 확인 후 서버 측 AI API 호출. 키는 서버 환경변수로만 설정
- `supabase/functions/payment-webhook/index.ts`: **결제 검증 미구현(501 응답)**. 잘못된 결제 성공 처리를 방지하기 위한 안전한 기본값
- `legacy/index.html`: 기존 6.0 전체 기능의 **별도 시연용 사본**. 7.0 계정·DB와 통합된 것은 아님
- `manifest.webmanifest`, `sw.js`, `assets/`: 아이폰 홈 화면 설치와 정적 화면 오프라인 캐시
- `config.example.js`: 클라이언트 공개 설정 샘플

## 빠른 시작

1. Supabase 새 프로젝트 생성 후 SQL Editor에서 `supabase/migrations/001_init.sql` 실행. **테스트 프로젝트에서 먼저 실행**하세요.
2. 프로젝트의 **URL**과 **anon/publishable key**를 확인하고 `config.example.js`를 `config.js`로 복사한 후 입력. `service_role` 키는 절대 브라우저에 넣지 마세요.
3. Supabase Auth 이메일 로그인/인증 및 Site URL, Redirect URLs를 실제 HTTPS 도메인으로 설정.
4. 폴더 전체를 HTTPS 정적 호스팅(Netlify 등)에 배포. `index.html`, `app.js`, `config.js`, `sw.js`, `manifest.webmanifest`, `assets/`, `legacy/`를 같은 루트에 두세요. 로컬 테스트는 `python3 -m http.server 8080`으로 가능합니다.
5. 실시간 채팅을 위해 Supabase Realtime 설정 및 publication 활성화를 확인하세요. SQL은 `messages` publication 등록을 포함합니다.
6. AI 기능을 쓰려면 Supabase CLI에서 `supabase functions deploy ai-coach`를 실행하고 `OPENAI_API_KEY`를 서버 비밀 환경변수로 설정하세요. 필요시 `OPENAI_MODEL`도 설정합니다. 인증 JWT 검증을 유지하세요.
7. 아이폰 Safari로 배포 주소 접속 → 공유 → 홈 화면에 추가.

## 기능 상태

| 기능 | 상태 |
|---|---|
| 통장 열기/닫기, 페이지, 테마 | 작동하는 프런트엔드 |
| 오프라인 UI/데모 기록 | 정적 캐시 및 로컬 저장(설치 후) |
| 이메일 가입/로그인 | Supabase 설정 시 작동 |
| 통장 클라우드 저장 | Supabase 설정 시 작동 (기존 로컬 기록 자동 이전 없음) |
| 1:1 실시간 텍스트 채팅 | Supabase 설정 시 작동; 실제 사용자 ID 공유 방식 |
| AI 코치 | 서버 함수 배포 + API 키 설정 시 작동; 이용량 제한은 미구현 |
| 전문가 예약 | 검증된 전문가 데이터를 운영자가 등록하면 신청 가능; 시간 중복 방지/승인 워크플로는 미구현 |
| 신고 | 로그인 시 접수 가능; 운영자 집계 RPC 제공, 신고 처리 화면은 미구현 |
| 결제 | **미구현**. PG 계약·서명 검증·서버 조회·웹훅 중복 방지 필요 |
| 음성 통화 | 미구현; 추후 WebRTC + TURN + 안전 정책 필요 |
| 기존 6.0 게임·클래스 | `legacy/index.html`에서 별도 시연 가능 |

## 보안·운영 필수 작업

- 공개 전: 이메일 인증, 비밀번호 정책, MFA(관리자), 인증 요청 및 채팅/AI 요청 레이트 리밋, 봇/스팸 방지, 악성 사용자 차단, 메시지 신고 및 운영자 처리 화면 구현.
- 1:1 방 생성 RPC는 대상 UUID가 존재하는지 검사하지만, 무단 대화방 생성 남용 방지와 수신자 동의(초대 수락)는 아직 없습니다. 운영 공개 전 필수입니다.
- Supabase RLS가 회원별 읽기/쓰기를 제한하지만, 별도 보안 테스트, 침투 테스트, 백업/복구, 모니터링, 비밀키 관리가 필요합니다.
- 실시간 채팅은 종단간 암호화(E2EE)가 아닙니다. 민감한 상담기록이나 의료정보를 수집하지 마세요.
- 예약은 전문가 자격 검증, 가용시간 슬롯 잠금, 취소/환불, 결제 연동, 동의서 등 운영 체계를 갖춘 뒤 공개하세요.
- 실제 금전 지급/상담료 결제는 PG 계약, 전자상거래/전자금융 관련 검토, 개인정보처리방침, 이용약관, 환불 정책, 세무 및 정산 설계 후 진행해야 합니다.
- 상담 서비스와 일반 대화 파트너를 구분하고, 상담 자격·감독·위기 대응·신고 프로세스를 수립하세요. 가상 포인트를 예금이나 현금과 혼동시키지 마세요.
- `sw.js`는 정적 화면을 캐시하지만 Supabase API나 사용자 데이터는 서비스워커에 캐시하지 않습니다. 오프라인에서는 클라우드 데이터 수정/채팅/예약/AI가 불가능합니다.
- 프로덕션 전 통합/접근성/기기별 PWA 테스트, 개인정보 영향 검토, 앱의 실제 운영 로그와 관리자 기능을 보완하세요.

## 결제 구현 순서

1. PG 사업자 및 결제 모델(구독/단건) 확정.
2. 서버에서 주문 생성, 금액/사용자/상품 스냅샷 고정.
3. PG의 결제 확인 API를 **서버에서** 호출하고 승인 금액·주문 ID·상태 일치 검증.
4. 웹훅 서명/재전송 방지·이벤트 중복 처리, 원자적 DB 트랜잭션으로 상태 갱신.
5. 환불/취소/구독 만료/정산/영수증/고객지원 테스트 후 운영 전환.

## 권장 로드맵 및 범위

- **1~2개월**: UX 검증, 회원가입, 기본 채팅, 기록, 데이터 삭제·내보내기, 약관 및 개인정보 설계.
- **3~4개월**: 안전 운영, 관리자 콘솔, 초대 동의, AI 제한·과금 모니터링, 예약 슬롯 관리.
- **5~6개월 이상**: PG 연동, 전문상담자 검증, 서비스 모니터링, 법률 검토, 시범 운영 및 보안 감사.

기간은 소규모 전담 개발팀 기준의 대략적 계획이며 실제 일정·비용은 범위에 따라 달라집니다.
